# «Легче» 2.0: инструкция по обновлению и настройке

Что здесь: как накатить обновление на GitHub, как вести базу рецептов и продуктов, как выпускать новые версии и как работают проверка версии и поиск по штрихкоду.

Предположения, которые стоит проверить: ваш логин на GitHub `caramelloblank-droid`, репозиторий называется `legche`, основная ветка `main`. Если это не так, исправьте файл `www/app-config.json` (см. раздел 6).

---

## 1. Что в архиве

| Что | Файлы | Действие |
|---|---|---|
| Приложение | `www/index.html`, `www/css/app.css`, `www/app-config.json`, `www/js/*.js` (17 файлов) | заменить или добавить |
| Рецепты и продукты | `content/foods.json`, `content/recipes.json`, `content/tips.json`, `content/manifest.json` | **новая папка** |
| Сборка | `.github/workflows/build-apk.yml` (заменить), `.github/workflows/content.yml` (новый), `ci/patch_android.py`, `ci/build_content.py` | заменить или добавить |
| Настройки проекта | `package.json`, `.gitignore`, `capacitor.config.json` | заменить |
| Тесты и документация | `tests/*`, `tools/recipes_src.py`, `docs/*`, `README.md` | заменить или добавить |

**Не меняйте и не удаляйте:** `ci/debug.keystore` (это ключ подписи; если он изменится, новая версия не установится поверх старой) и папку `assets/`.

Можно удалить старые тесты `tests/smoke.py`, `tests/safety.py`, `tests/restore.py` (они от версии 1). Это не обязательно.

В `www/js/` должно быть 17 файлов: `app.js, calc.js, exercises.js, extras.js, foods.js, game.js, move_ui.js, notify.js, online.js, periods.js, plan.js, plan_ui.js, store.js, strength.js, ui.js, util.js, views.js`.

## 2. Накатываем патч на GitHub

### Способ А: через браузер (проще всего)

1. Скачайте `legche-2.0.zip` и распакуйте. Внутри папка `legche`.
2. Покажите скрытые файлы, иначе папка `.github` не загрузится (Windows: Проводник → Вид → Показать → Скрытые элементы; Mac: Cmd+Shift+точка).
3. В репозитории нажмите **Add file → Upload files**.
4. Откройте распакованную папку `legche`, выделите **всё её содержимое** (не саму папку) и перетащите в окно браузера. Дождитесь, пока загрузятся все файлы и папки.
5. Внизу выберите **Commit directly to the main branch** и нажмите **Commit changes**. Файлы с теми же именами заменятся автоматически.
6. Проверьте на главной странице репозитория: есть папки `content`, `tools`, `.github`, и в `.github/workflows` два файла: `build-apk.yml` и `content.yml`.

**Если папка `.github` не загрузилась.** Создайте файлы вручную: Add file → Create new file, в имени введите `.github/workflows/build-apk.yml`, вставьте содержимое одноимённого файла из архива и сохраните. Повторите для `content.yml`.

**Если на шаге 4 не хватает файлов** (браузер ограничивает число файлов в одной загрузке): повторите загрузку по частям: сначала `www`, затем `content`, `ci`, `tests`, `tools`, `docs`, `.github`, остальные файлы из корня.

### Способ Б: через git

```
git clone https://github.com/caramelloblank-droid/legche.git
cd legche
# скопируйте содержимое архива поверх (с заменой файлов)
git add -A
git commit -m "Легче 2.0"
git push
```

### Требование к репозиторию

Репозиторий должен быть **публичным** (Settings → General → Danger Zone → Change visibility). Иначе приложение не сможет скачивать рецепты и проверять версию. Личных данных в репозитории нет: они хранятся только на телефонах.

## 3. Выпуск 2.0.0 и установка

1. **Releases → Draft a new release.** В поле тега введите `v2.0.0` и выберите **Create new tag on publish**. Название: `Легче 2.0.0`. Нажмите **Publish release**.
2. Вкладка **Actions**: сборка идёт 10–15 минут. Дождитесь зелёного статуса.
   - Если рядом с зелёным статусом жёлтое предупреждение «Сборка со сканером штрихкодов не удалась», это нормально: приложение собрано **без камеры**, всё остальное работает, штрихкод вводится вручную. Если хотите камеру, пришлите мне лог.
   - Если красный: откройте красный шаг и пришлите последние 30–40 строк.
3. В релизе в разделе **Assets** появится `Legche-2.0.0.apk`.
4. **Сначала на телефоне со старой версией:** Настройки → Данные → **Сохранить копию** (и ещё **Копировать текстом**: двойная защита).
5. Скачайте APK с телефона и установите **поверх** старой версии. Данные сохранятся: подпись та же.
   - Если Android пишет, что приложение не установилось (конфликт подписи): удалите «Легче» и установите заново, затем верните данные: Настройки → **Загрузить из файла** или **Восстановить из текста**.
6. После запуска появится окно «Что нового в 2.0». Дальше:
   - Настройки → **Инвентарь**: укажите гантели (минимум, максимум, шаг), степпер (допустимый вес по паспорту), резинки (если уже заказали).
   - Настройки → **Моя кухня**: отметьте технику (мультиварка уже отмечена; если микроволновка есть, отметьте).
   - Раздел «Движение» → **Проверка силы**.
   - Настройки → **Напоминания** → Тест → **Диагностика напоминаний** (проверьте все пункты зелёные).

## 4. База продуктов и рецептов

Файлы лежат в папке `content/` репозитория. Приложение берёт встроенную копию из APK и подгружает более новую из репозитория. **Переустанавливать APK не нужно.**

### Как редактировать на GitHub

1. Откройте файл, например `content/recipes.json`.
2. Нажмите значок карандаша справа вверху.
3. Внесите изменения (см. форматы ниже). Нажмите **Commit changes**.
4. Откройте **Actions**: запустится «Проверка рецептов и продуктов». Если он **зелёный** ✅, всё в порядке, и робот сам обновит `manifest.json` (версию и контрольную сумму). Если **красный** ❌, откройте шаг: там написано, где ошибка (файл, id, поле).
5. Телефоны скачают обновление при запуске (не чаще раза в 12 часов) или по кнопке: Настройки → Онлайн-функции → **Обновить рецепты и продукты**.

Если вы ошиблись: откройте файл → History → найдите прежний коммит → **Revert**. Либо на телефоне: «Вернуться к встроенным данным».

### Добавить продукт (`content/foods.json`)

Каждая строка файла: один продукт. Все значения **на 100 г**. Новый продукт добавляйте перед последней строкой `]`, не забывая запятую после предыдущего.

```json
{"n":"Творог 5% «Простоквашино»","k":121,"p":17.2,"f":5,"c":1.8,"cat":"Молочные продукты"},
{"n":"Яйцо куриное","k":157,"p":12.7,"f":11.5,"c":0.7,"cat":"Яйца","ug":55,"ul":"шт","syn":["яйца","яичко"]}
```

| Поле | Что это | Обязательно |
|---|---|---|
| `n` | название (не должно повторяться) | да |
| `k` | ккал на 100 г | да |
| `p`, `f`, `c` | белки, жиры, углеводы на 100 г | да |
| `cat` | категория (как у остальных продуктов) | рекомендуется |
| `ug` и `ul` | вес одной порции или штуки в граммах и её название (`шт`, `порция`, `ломтик`, `стакан`) | нет |
| `syn` | другие названия для поиска | нет |

Правила: для круп и мяса различайте **сухой/сырой** и **варёный/готовый** вид в названии, например «Гречка (сухая)» и «Гречка варёная». Ингредиенты рецептов считаются в сухом и сыром виде.

### Добавить рецепт (`content/recipes.json`)

```json
{"id":"l41","name":"Куриный суп с вермишелью","meal":"l","cost":1,"servings":4,
 "activeMin":15,"totalMin":45,"tags":["soup","poultry"],
 "ingredients":[["Куриное бедро без кожи (сырое)",130],["Вермишель (сухая)",25],["Морковь сырая",40]],
 "methods":[
  {"type":"stove","timeMin":45,"steps":["Курицу варите 25 минут","Добавьте овощи и вермишель, варите 10 минут"]},
  {"type":"multicooker","timeMin":50,"tempC":100,"fill":"до 2/3 чаши","delayStart":false,"steps":["Выложите всё в чашу, залейте водой","Варите до сигнала"]}
 ],
 "tips":"Подавайте со свежей зеленью","keep":"2 дня в холодильнике"}
```

| Поле | Значение |
|---|---|
| `id` | уникальный код: `b…` завтрак, `l…` обед, `d…` ужин, `s…` перекус и число |
| `meal` | `b`, `l`, `d` или `s` |
| `cost` | 1 дёшево, 2 средне, 3 дорого |
| `ingredients` | `[название, граммы на одну порцию]`; **название точно как в `foods.json`** |
| `methods[].type` | `stove` плита, `oven` духовка, `multicooker` мультиварка, `blender`, `toaster`, `microwave`, `none` (без готовки) |
| для `oven` и `multicooker` | **обязательны** `timeMin` и `tempC` |
| `methods[].also` | дополнительная техника, например `["blender"]` |
| `methods[].tool` | для блендера: `immersion` (погружной) или `chopper` (чаша-измельчитель) |
| `steps` | шаги. Если в шаге написано «10 минут», у него появится кнопка таймера |
| `tags` | `fish` и `legume` участвуют в правилах недели (рыба ≥ 2 дней, бобовые 2–3), остальные для поиска |

Калорийность порции должна быть разумной для типа приёма (завтрак 250–620, обед 330–720, ужин 250–640, перекус 90–330): приложение само увеличит или уменьшит граммы под норму человека.

### Советы дня (`content/tips.json`)

Простой список строк. Добавляйте строки через запятую.

### Если нужно массово перегенерировать рецепты

Исходник в компактном формате лежит в `tools/recipes_src.py`: `python3 tools/recipes_src.py` создаёт `content/recipes.json`. Обычно проще править JSON напрямую.

## 5. Проверка новой версии приложения

Как это работает: при запуске (не чаще раза в сутки) приложение спрашивает GitHub: «какой последний релиз?» Если тег новее установленной версии, на экране «Сегодня» появляется баннер **«Доступна версия X»** с кнопками **Скачать** (откроется страница релиза), **Что нового** и **Позже** (напомнит через 3 дня). Ничего не устанавливается без вас.

Как выпустить обновление:

1. Внесите изменения в репозиторий.
2. **Releases → Draft a new release**, тег по образцу `v2.0.1` (три числа через точку, `v` в начале). Publish.
3. Через 10–15 минут в релизе появится APK. Текст вашего релиза показывается в приложении по кнопке «Что нового», поэтому пишите в нём коротко, что изменилось.
4. На телефонах баннер появится в течение суток; сразу: Настройки → Онлайн-функции → **Проверить версию приложения**.

Номер версии приложения берётся из тега (`v2.0.1` → 2.0.1), поэтому тег обязателен именно в таком формате.

Проверить вручную можно в браузере: `https://api.github.com/repos/caramelloblank-droid/legche/releases/latest`. В ответе должно быть поле `tag_name`.

Если нужно, чтобы старые версии не пытались скачать несовместимый контент, поднимите `minApp` в `content/manifest.json` (например, `"2.1.0"`): приложения младше этой версии контент пропустят.

## 6. Подключение Open Food Facts (штрихкоды)

Ключи и регистрация **не нужны**. Open Food Facts — открытая общедоступная база продуктов.

### Как это устроено

- Кнопка **Штрихкод** в окне поиска продукта (при добавлении еды).
- Вы наводите камеру (если собралась со сканером) или вводите цифры вручную.
- Приложение сначала ищет штрихкод **у себя** (в памяти, без интернета), затем в Open Food Facts: `https://world.openfoodfacts.org/api/v2/product/<штрихкод>.json`.
- Из ответа берутся название, бренд, ккал, белки, жиры, углеводы на 100 г и размер порции. Если нет калорийности, форма «Свой продукт» откроется с подставленными данными, и вы допишете с упаковки.
- Найденный или введённый продукт **сохраняется вместе со штрихкодом**: повторно он находится мгновенно и без интернета. Сохранённые продукты входят в резервную копию.
- Из приложения уходит **только штрихкод** и название программы с версией (требование Open Food Facts), никаких данных о вас.
- Счётчик «найдено X из Y» виден в окне штрихкода и в «Диагностике».

### Где настраивается

Файл `www/app-config.json`:

```json
{
  "version": "2.0.0",
  "repo": "caramelloblank-droid/legche",
  "branch": "main",
  "contentBase": "https://raw.githubusercontent.com/caramelloblank-droid/legche/main/content/",
  "offApi": "https://world.openfoodfacts.org/api/v2/product/"
}
```

- `repo`, `branch` и `contentBase` нужно поправить, если название репозитория или ветки у вас другие.
- `offApi` менять не нужно. Если когда-нибудь захотите другую базу, нужно поправить функцию `parse` в `www/js/online.js` (напишите мне).

### Как проверить, что работает

1. В браузере на компьютере откройте: `https://world.openfoodfacts.org/api/v2/product/3017620422003.json?fields=product_name,nutriments`. Должен прийти JSON с названием и питательностью.
2. На телефоне: Дневник → Добавить → **Штрихкод** → введите те же цифры → **Найти**. Продукт появится в списке; выберите порцию и добавьте.
3. Отключите интернет и введите те же цифры ещё раз: продукт найдётся из памяти.

### Что нужно знать

- Российские товары в Open Food Facts представлены **неполно**: данные добавляют пользователи. Всегда сверяйте с упаковкой. Поэтому раздел экспериментальный: через пару недель посмотрите счётчик «найдено X из Y».
- Пополнить базу для всех можно, сфотографировав упаковку в приложении Open Food Facts (оно бесплатное). Приложение «Легче» этого само не делает.
- Камера работает через плагин с модулем Google. Нужны сервисы Google Play на телефоне; при первом запуске модуль может скачаться. Если камера недоступна, остаётся ручной ввод.

## 7. Частые проблемы

| Проблема | Что делать |
|---|---|
| Красный запуск «Проверка рецептов и продуктов» | Откройте шаг, прочитайте строку «ОШИБКИ В КОНТЕНТЕ»: там файл и поле. Исправьте и сохраните ещё раз |
| Приложение не видит новые рецепты | Репозиторий должен быть публичным; проверьте `contentBase` в `app-config.json`; Настройки → «Обновить рецепты и продукты»; «Диагностика» покажет ошибку |
| Баннер «Доступна версия» не появляется | Тег в формате `v2.0.1`, релиз опубликован (не черновик и не pre-release), репозиторий публичный |
| Не приходят напоминания | Настройки → Диагностика напоминаний; затем «Без ограничений» для батареи и «Автозапуск» |
| Сборка красная | Пришлите последние 30–40 строк лога красного шага |
| Нужно вернуть данные | Настройки → Данные → **Загрузить из файла** или **Восстановить из текста** |

## 8. Проверьте на телефоне после установки

1. Инвентарь сохранился, степпер включён только после ввода допустимого веса.
2. «Проверка силы» → тренировка: вес гантели подобран из вашего диапазона.
3. План → Корзина: список сгруппирован по отделам, «есть дома» вычитает продукт.
4. Рецепт открывается, мультиварка показывает время и температуру, «Готовить по шагам» работает, таймер звенит.
5. Включён чекбокс «Готовка в мультиварке»: в меню недели доля мультиварки выросла, но блюд на плите и в духовке тоже хватает.
6. Событие: создайте застолье на сегодня, проверьте, что кольцо калорий скрыто, а серия не прерывается. Удалите событие.
7. Напоминания: «Тест уведомления» приходит.
8. Штрихкод: попробуйте 5–10 привычных продуктов и запишите, сколько нашлось.
9. Удалите запись в дневнике: должна появиться кнопка «Отменить».
10. Сделайте резервную копию.
